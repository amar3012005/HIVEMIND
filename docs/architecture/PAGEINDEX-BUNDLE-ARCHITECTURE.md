# PageIndex Bundle Architecture

> Evolving PageIndex from a pointer-only hierarchy into a materialized project knowledge layer with sub-millisecond recall.

## Status: PLANNED (not yet implemented)

**Owner:** Amar  
**Last Updated:** 2026-05-27  
**Related Files:** See [Current Codebase](#current-codebase) below

---

## 1. Problem Statement

PageIndex today stores **memory IDs organized by topic/project** in a 4-level tree (`/hivemind/projects/<slug>/[hall|tag]`). Every recall query still hits Qdrant (30-80ms) or PostgreSQL full-text (5-20ms) even when the answer is a well-known project fact that could be served from a pre-computed snapshot.

**Goal:** Serve 80%+ of project-scoped recall queries from a materialized JSONB bundle in < 2ms, falling back to existing search tiers only when the bundle cannot answer.

```
Query → PageIndexSearcher.search()
  ├── [50ms timeout] PageIndex hierarchical lookup (node memoryIds → fetch memories)
  ├── [parallel] Direct hybrid search (PostgreSQL FTS + Qdrant vector)
  └── Merge + deduplicate + rank
```

- `pageindexSearcher` initialized at startup from `search/pageindex-searcher.js`

## 3. Proposed Architecture (v2 — Bundle Layer)

### 3.1 New Schema Columns on `PageIndexNode`

```sql
ALTER TABLE "PageIndexNode" ADD COLUMN "bundle"              JSONB     DEFAULT NULL;
ALTER TABLE "PageIndexNode" ADD COLUMN "bundle_built_at"     TIMESTAMPTZ DEFAULT NULL;
ALTER TABLE "PageIndexNode" ADD COLUMN "bundle_version"      INTEGER   DEFAULT 0;
ALTER TABLE "PageIndexNode" ADD COLUMN "bundle_stale"        BOOLEAN   DEFAULT TRUE;
ALTER TABLE "PageIndexNode" ADD COLUMN "bundle_trigger_count" INTEGER  DEFAULT 0;
```

**Only project-root nodes (depth=3, nodeType='project') get bundles.** Hall/tag/topic nodes do not — they remain pointer-only.

### 3.2 Bundle JSONB Shape

```jsonc
{
  "version": 14,
  "builtAt": "2026-05-27T10:30:00Z",
  "memoryCount": 342,

  // Top-N most important facts (capped at 50)
  "keyFacts": [
    { "id": "mem_abc", "fact": "Acme uses Nango for OAuth", "tags": ["nango", "oauth"], "weight": 0.95 },
    // ...
  ],

  // Entity registry (capped at 200 entries)
  "entityMap": {
    "person:dipesh": { "mentions": 12, "lastSeen": "2026-05-26", "context": "CTO, Salesforce lead" },
    "tool:nango": { "mentions": 8, "lastSeen": "2026-05-27", "context": "OAuth provider, self-hosted v0.70.3" },
    // ...
  },

  // Hall index: sub-tree summaries for fast scoping
  "hallIndex": {
    "engineering": { "memoryCount": 120, "topTags": ["api", "deploy", "prisma"], "summary": "..." },
    "sales": { "memoryCount": 45, "topTags": ["pipeline", "quota"], "summary": "..." },
    // ...
  },

  // Flattened tag cloud with frequencies
  "tagCloud": { "nango": 8, "oauth": 12, "deploy": 34, "prisma": 22 },

  // Recent activity timeline (last 20 events)
  "timeline": [
    { "date": "2026-05-27", "event": "Deployed connector framework v2", "memoryId": "mem_xyz" },
    // ...
  ]
}
```

**Size constraints:**
- `keyFacts`: max 50 entries
- `entityMap`: max 200 entries
- `timeline`: max 20 entries
- Total bundle target: < 100KB JSONB (Postgres TOAST handles larger, but keep it lean)

### 3.3 Rebuild Trigger: Per-Ingestion with Debounce

**Every project-scoped ingestion triggers a bundle rebuild** — not threshold-based. This eliminates staleness entirely.

```
Memory ingested into project X
  → SET bundle_stale = TRUE on project node
  → Debounce: schedule rebuildBundle(projectNodeId) in 3 seconds
  → If another ingestion arrives within 3s: reset timer
  → No more ingestions for 3s: rebuild fires ONCE
  → Rebuild completes: SET bundle_stale = FALSE, bundle_version++
```

**During stale window (between ingestion and rebuild):**
- Recall skips bundle tier → falls through to Hall Index → Qdrant
- No stale data served, ever

**Burst handling:**
- 50 rapid ingestions = 1 rebuild (debounce collapses them)
- Single ingestion = 3s delay to fresh bundle (acceptable)

### 3.4 Three-Tier Recall Hierarchy

```
                                    ┌─────────────────┐
                          Tier 1    │  Bundle Lookup   │  ~1ms
                          (if not   │  (JSONB read)    │  Project-scoped facts
                           stale)   └────────┬────────┘
                                             │ miss or stale
                                    ┌────────▼────────┐
                          Tier 2    │  Hall Index      │  ~5ms
                                    │  (node memoryIds │  Topic-scoped lookup
                                    │   + PG fetch)    │
                                    └────────┬────────┘
                                             │ miss
                                    ┌────────▼────────┐
                          Tier 3    │  Qdrant Vector   │  30-80ms
                                    │  + PG FTS hybrid │  Full semantic search
                                    └─────────────────┘
```

**Recall router logic:**
```javascript
async recall(query, { userId, orgId, project }) {
  // Tier 1: Bundle (only if not stale)
  if (project) {
    const node = await getProjectNode(userId, project);
    if (node?.bundle && !node.bundleStale) {
      const answer = matchFromBundle(query, node.bundle);
      if (answer.confidence > 0.7) return answer;
    }
  }

  // Tier 2: Hall Index (existing PageIndex search, 50ms timeout)
  const hallResults = await pageindexSearcher.search(query, { userId, orgId, project });
  if (hallResults.length > 0 && hallResults[0].score > 0.6) return hallResults;

  // Tier 3: Full hybrid (Qdrant + PG FTS)
  return await directHybridSearch(query, { userId, orgId, project });
}
```

**Scope:** Auto-trigger on every project-scoped ingestion

1. Modify `pageindex-hook.js` to set `bundleStale = true` after classification

3. On debounce fire → call `BundleBuilder.rebuildBundle(projectNodeId)`

**Validation:** Ingest memories via MCP → verify bundle auto-rebuilds after 3s quiescence.

### Phase 3: Recall Fast-Path Wiring

**Scope:** Wire bundle into recall pipeline as Tier 1

1. Modify `pageindex-searcher.js` to check bundle first
2. Wire into `recall-router.js` (currently PageIndex not connected there)
3. Add bundle match scoring logic (keyword overlap + entity presence)
4. Add metrics: `bundle_hit`, `bundle_miss`, `bundle_stale_skip`

**Validation:** Recall queries show `source: "bundle"` in response metadata when bundle answers.

## 6. Risk Analysis

| Risk | Severity | Mitigation |
|------|----------|------------|
| Hot project = frequent rebuilds | Medium | Debounce (3s) collapses bursts into single rebuild |
| JSONB blob grows too large | Medium | Hard caps: 50 keyFacts, 200 entities, 20 timeline events |
| Stale bundle served | Low | `bundleStale` flag — recall skips bundle when true |
| Builder fails mid-rebuild | Low | Rebuild is idempotent; old bundle stays until new one succeeds |
| Migration on live `PageIndexNode` table | Low | All new columns nullable with defaults, no data migration needed |
| Recall-router not currently wired to PageIndex | Medium | Phase 3 requires careful integration — test with feature flag |

## 7. Trigger Semantics

**What counts as "project-scoped ingestion":**
- `hivemind_save_memory` with `project_id` set
- `hivemind_ingest_code` with `project` field
- Any memory that `pageindex-hook` classifies under a project subtree
- Tag-based association (e.g. `project:hivemind`) counts IF the hook resolves it to a project node

**What does NOT trigger bundle rebuild:**
- Global memories (no project association)
- PageIndex evolution agent operations (prune/split/merge)
- Manual tree edits (custom branches)

## 8. Bundle Matching Algorithm (Tier 1)

For a given recall query:

1. **Extract query keywords** (stopword-filtered, stemmed)
2. **Check keyFacts:** Jaccard overlap between query keywords and fact tags. Score > 0.7 = hit.
3. **Check entityMap:** If query mentions a known entity name → return entity context + related keyFacts.
4. **Check tagCloud:** If query keywords match high-frequency tags → narrow to matching hall, delegate to Tier 2 with hall scope.
5. **Timeline check:** If query is temporal ("what happened yesterday", "recent changes") → return timeline entries.

Confidence threshold: 0.7. Below that → fall through to Tier 2.

## 9. Open Questions

1. **Should bundle include embeddings?** Pre-computed embeddings for keyFacts would enable semantic match at Tier 1. Adds ~50KB to bundle. Tradeoff: faster semantic match vs larger JSONB.

2. **Multi-project queries?** Query spanning two projects needs bundles from both. Current design is single-project. May need a "meta-bundle" or just fall through to Tier 3.

3. **Bundle TTL hard cap?** Even with per-ingestion rebuild, should we force-rebuild every 24h to catch graph-edge updates the ingestion hook doesn't see?

4. **Connector-sourced memories (Gmail, Slack, etc.)?** Bulk ingestion from connectors produces many memories rapidly. Debounce handles this, but verify 3s debounce sufficient for connector bulk import that may run 5-10 minutes.
