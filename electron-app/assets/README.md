# SINGULANCE desktop assets

`icon.png` is the 1024×1024 SINGULANCE cyan orbit mark on a white rounded tile, matching the product login-page logo. Electron Builder converts it into the packaged Mac icon automatically.

`wordmark.png` supplies the SINGULANCE splash wordmark. The splash also displays `icon.png`.

`tray-icon.png` is the separate monochrome macOS menu-bar template icon; keep it monochrome so it adapts to light and dark menu bars.


`frontend/` is generated by `scripts/bundle-frontends.cjs` from the pinned outer build, Open Dot static output and Runtime public browser artifacts. It contains no cookies, credentials, tenant history or agent execution runtime. Electron serves those bytes at their existing HTTPS origins so existing authentication, CSP, APIs and live updates retain their server ownership. Native combo revisions must match exactly; unmatched artifacts use the live server to preserve release compatibility. Next route documents and server actions remain remote. Frontend snapshots ship with application updates; development builds may still use the hosted frontend.

## Encrypted saved conversations (v2.1.5)

View → **Saved Conversations (Offline)…** opens read-only copies of the message windows you have viewed in Runtime, DSH employees, and Open Dot employees. The cache reads their existing rendered conversation projections; it does not fetch an extra journal, modify the native agent loop, or hydrate a live controller from stale events. Unvisited/older pages and attachment files remain server-owned. Live switching continues using the retained frontend and server live store.

Records use AES-256-GCM with account-and-room authenticated data. A random device key is wrapped with Electron's asynchronous macOS Keychain `safeStorage`; no plaintext fallback is used. Account identity comes only from the existing authenticated bootstrap response, never from a renderer-supplied tenant ID. Sign-out clears the current account's copies; account changes cannot reuse a previous account's mounted view. Offline copies lock after 24 hours without account verification and expire after seven days. The current account is bounded to 40 rooms / 20 MiB, with bounded rendered message windows. All local files are private to the OS user.

The offline window has no composer, approval controls, external images, network access, or executable artifact content. Reconnecting returns to the live app; no actions are queued or replayed. “Clear offline copies” affects only local copies, not server conversation history. The Keychain must be available to save or unlock copies. The local ad-hoc build remains separate from notarized/MAS distribution.

### Cached-first normal conversations

The desktop now mounts a read-only saved transcript in the existing conversation
area while the native DSH or Open Dot room is loading. It uses the authenticated
account and exact room, renders the newest 30 saved messages, and loads earlier
saved messages in 30-message pages. Navigation removes the old transcript; the
native view takes over when ready. Cached approvals and tool actions are never
replayed. First visits still need server history, and cache capture covers only
messages previously rendered on this Mac. Initial account verification remains
required; the separate offline viewer can reopen the bounded saved copy offline.

Open Dot's existing authenticated history endpoint now supports 50-message cursor
pages rather than eagerly fetching 1,000 messages. DSH retains its native paged
journal and assembler. The native server is authoritative for newly received,
edited or removed messages.
