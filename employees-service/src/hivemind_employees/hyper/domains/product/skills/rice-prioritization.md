when: several candidate features or bets compete for one cycle and the ranking is being argued from opinion or seniority

RICE SCORING method (Sean McBride, Intercom growth team):
1. REACH — how many users or events this touches in ONE fixed period. Use a real count from a real source (weekly actives on the screen, monthly checkout attempts), not "most users". State the period explicitly; scores across different periods are not comparable.
2. IMPACT — per-user effect on the target outcome, on Intercom's fixed scale: 3 = massive, 2 = high, 1 = medium, 0.5 = low, 0.25 = minimal. Pick one and say which outcome it moves.
3. CONFIDENCE — a discount for how much you actually know: 100% = shipped evidence or a completed test, 80% = partial evidence, 50% = gut feel. Anything below 50% is not a candidate, it is a research task.
4. EFFORT — total person-months across ALL functions (design, eng, data, support), not eng-only. Never below 0.5.
5. SCORE = (Reach x Impact x Confidence) / Effort. Publish the full table with every input visible, so the argument moves from the ranking to the estimate that produced it.
6. SANITY PASS — the score is a prompt for discussion, not a verdict. Override it out loud when a low scorer is a dependency, a legal obligation, or a strategic wedge; record the override and the reason. Never quietly retune inputs to reach a preferred answer — that is the one failure mode that destroys the framework's value.
